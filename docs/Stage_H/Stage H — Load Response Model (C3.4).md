# Stage H — Load Response Model (C3.4)

## 1. Назначение

Документ задаёт **формальную модель вычисления реакции системы на нагрузку**  
в рамках архитектуры NeuroTransAnalytics v4.

Stage H реализует:

> переход системы из состояния baseline в состояние load  
> и количественную оценку этого перехода.

---

## 2. Принципиальная постановка

### 2.1. Тип задачи

Stage H решает задачу:

> **оценки изменения поведения системы при внешнем воздействии**

а не:
- анализа структуры стимулов,
- восстановления параметров теста,
- оценки вариативности как таковой.

---

### 2.2. Формализация состояния

Система рассматривается в двух состояниях:

State_0 = baseline
State_1 = load


где:

- **baseline** — реакция без дополнительной когнитивной нагрузки  
- **load** — реакция при наличии дополнительной задачи (dual-task)

---

### 2.3. Наблюдаемая величина

Наблюдаемыми являются:

- RT
- ΔV1
- ΔV4
- ΔV5/MT

---

## 3. Основная модель

### 3.1. Базовое определение

Для любой метрики \( X \):

LoadResponse(X) = F( X_load , X_baseline )


---

### 3.2. Допустимые формы функции F

#### 1. Отношение (основная форма)

LR_ratio = X_load / X_baseline


Интерпретация:
- > 1 — замедление под нагрузкой
- = 1 — отсутствие эффекта
- < 1 — ускорение (редкий случай)

---

#### 2. Относительное изменение

LR_delta = (X_load - X_baseline) / X_baseline

---

#### 3. Логарифмическая форма (рекомендуется для стабильности)

LR_log = log( X_load / X_baseline )

Преимущества:
- симметрия
- аддитивность
- устойчивость к масштабам

---

## 4. Уровни вычисления

### 4.1. Event-level (опционально)

LR_event = F( X_load_event , X_baseline_event )


Требование:
- строгая сопоставимость событий

Используется редко (высокий шум).

---

### 4.2. Test-level (основной уровень)

Для каждого теста:

LR_T1 = F( RT_load_T1 , RT_baseline_T1 )
LR_V4 = F( ΔV4_load , ΔV4_baseline )
LR_V5MT = F( ΔV5_load , ΔV5_baseline )

---

### 4.3. Session-level

Агрегация по тестам:

LR_session = Aggregate( LR_T1 , LR_V4 , LR_V5MT )


---

## 5. Выбор базовой метрики

### 5.1. Приоритет

1. ΔV4  
2. ΔV5/MT  
3. ΔV1 (с ограничениями)  
4. RT (контрольная)

---

### 5.2. Ограничения

- ΔV1 содержит моторный компонент → снижает чистоту интерпретации  
- RT = сумма → не специфичен  

---

## 6. Агрегация

### 6.1. Требования

Агрегация должна быть:

- устойчивой к выбросам
- воспроизводимой
- интерпретируемой

---

### 6.2. Допустимые методы

median(LR)
trimmed_mean(LR, 10–20%)

---

## 7. Load Profile

### 7.1. Определение

LoadProfile = [
LR_T1,
LR_V4,
LR_V5MT
]

---

### 7.2. Расширение

Допускается:

LoadProfile_ext = [
LR_T1,
LR_V4,
LR_V5MT,
variability_shift,
error_rate_shift
]


---

## 8. Интерпретация (граница C4)

### 8.1. Базовые режимы

| Значение | Интерпретация |
|----------|--------------|
| ≈ 1      | устойчивость |
| > 1      | снижение эффективности |
| >> 1     | высокая чувствительность к нагрузке |

---

### 8.2. Профильная интерпретация

- ΔV4 ↑ → нагрузка на цветовое распознавание  
- ΔV5/MT ↑ → нагрузка на движение  
- дифференцированные изменения → диссоциация архитектур

---

## 9. Связь с архитектурой v4

Stage H:

- принадлежит **C3.4 (Scenario Engine)**
- использует:
  - ComponentTiming
  - AggregateMetrics (baseline/load)
- не изменяет raw данные

---

},

}


---

## 11. Версионность

Обязательно фиксируется:

- формула F
- уровень агрегации
- набор метрик
- параметры фильтрации

---

## 12. Инварианты

1. baseline и load — независимые состояния  
2. raw данные неизменяемы  
3. сопоставление выполняется на уровне тестов  
4. Load Index — производная величина  
5. вычисления только в C3.4  

---

## 13. Итог

Stage H — это:

> **формализованная оценка изменения временных компонент реакции  
> при переходе системы из baseline в состояние нагрузки**

и основная операция:

LoadResponse = F(load / baseline)

без использования структуры стимулов как источника нагрузки.
